# VIZ refactor roadmap

Living tracker for the code-quality refactor of the VIZ app. Working cadence: **scope → one small bite → `npm run build` + `npm run typecheck:gate` (ratcheting tsc baseline) → eyeball in `npm run dev` → commit.** Each bite is behavior-preserving unless explicitly a bugfix.

## Done (2026-06)

**Tier 1 — quick wins:** deleted dead `style.css`; fixed a collapsible-arrow violation; `window.confirm` → promise-based `showConfirm()` (modals.ts); verified hotkey badges.

**Tier 2 — dedup:** inline `<style>` (~1,960 lines) → imported `app.css`; design tokens (`--color-*`) + `PRIMARY_COLOR`; window chrome → `.window-header`/`.window-min-btn` classes; DOM factories (`el`/`byId`/`makeButton`/`makeOption`) in `utils.dom.ts`; `createCollapseToggle()` (replaced ~15 hand-rolled setters); shared `utils.export.ts` (CSV/Excel); `icons.ts` registry + `createConditionsButton()`.

**Tier 3 — decomposition (partial):**
- A: icon registry (`icons.ts`), pure helpers → utils.
- B: **all** static DOM refs → `dom-refs.ts` (main.ts no longer queries the DOM at top level).
- C1 (selection.ts, partial): hit-test geometry → `selection-geometry.ts`; marching-ants CSS → `app.css`. 1,830 → ~1,496.
- C2 (rendering.ts): pure color/expression/numeric helpers → `rendering-helpers.ts`. 1,136 → ~985.

**Bugs fixed along the way (pre-existing/latent):** rectangle selection under non-zero map pitch/bearing; vertical slider browser-compat (`appearance: slider-vertical` removed in Chrome 121); flash of empty panels + lingering legend on load; legacy normalization-radio indirection torn out (now plain `<select>`s); numeric-paint ramp-row state-leak.

## Lessons learned (apply these to remaining work)
1. **Verify with build + the tsc gate + a per-bite eyeball.** `npm run build` (esbuild) does not type-check; `npm run typecheck:gate` is the real check (ratcheting baseline in `scripts/typecheck-gate.cjs`) — watch the delta, not the absolute.
2. **God-modules don't split cleanly where module-local mutable `let` state + callback seams are shared.** Clean, low-risk extractions are *pure* or *S-only* helpers (geometry, color/expression primitives). Deeper splits (tool handlers, panel builders) need the shared state hoisted into an object — real churn, medium risk; only worth it for maximal decomposition.
3. **Prefer verbatim / script-assisted moves** for big mechanical extractions (dom-refs, rendering-helpers, marching-ants) so the diff is reviewable and the compiler proves completeness.
4. **TS narrows local `const | null` inside closures but not imported ones** — always-present elements in `dom-refs.ts` are typed non-null.
5. **Watch for dropdown↔hidden-legacy-radio indirection** (normalization had it; colorMode still does). It's an anti-pattern and a source of state-leak bugs.
6. Several "regressions" surfaced during eyeballs were pre-existing latent bugs exposed by closer testing — the disciplined eyeball is worth it.

### Medium value, medium risk
- **E1 — feature-owned init (the real `main.ts` slimmer).** 🔄 In progress. Each feature module imports its refs directly from `dom-refs.ts` instead of receiving them via `initXxxElements(...)`. Pattern (proven on legend): replace the module's `let _ref` + `initXxxElements` with a top-level `import { ... } from './dom-refs'` (names already match), delete the `initXxxElements` call + import in `main.ts`, and drop any now-unused ref imports from `main.ts` (keep refs `main.ts` still uses itself). Direct import is also strictly safer (refs bound at load, never `undefined`). **Done:** `legend`, `scatterplot`, `rendering`, `modals`, `land-schedule`, `layers`, `statistics`, `position`/windows. Each now imports its plain DOM refs directly from `dom-refs` (modules using `_foo` names alias the import: `import { foo as _foo }`); the two subject-selector modules (`scatterplot`, `statistics`) keep their constructed `SubjectSelectorControls` bundle injected via a slimmed `initXxxElements`. Notes: (1) a module's plain refs move to direct imports even when main.ts *also* uses them for its own listeners — both just import the same dom-ref; only refs main.ts no longer references at all get pruned from main.ts's import block (the strict `noUnusedLocals` gate lists them). (2) `modals`' 43 form-field refs had never been migrated to `dom-refs` (they were inline `getElementById` in main.ts) — added them to `dom-refs` as part of this.
**Side-effect modules (now done too):** `filters`, `time-adjustment`, `comp-finder` — their init bodies bind listeners / build widgets / call render fns, so rather than a mechanical ref swap, the refs moved to `dom-refs` imports while the init function stayed (now parameterless, or callback-only) and main.ts still calls it *at the same point in the sequence* — preserving init order. `time-adjustment`'s `showFiltersPanel` and the bundled els-object became a module-level `const els` built from dom-refs + an injected `_showFiltersPanel` callback; `time-adjustment` + `comp-finder` had ~30 refs each that were inline `getElementById` in main.ts — migrated to `dom-refs` (like modals).
`selection`'s `initSelectionElements()` takes no refs (it creates SVG elements + binds document listeners) — left as-is. The `initXxxCallbacks(...)` seams are left alone — that's E2.

**E1 is complete.** Every feature module now owns its DOM refs via `dom-refs` imports; main.ts no longer threads element objects into any module. The remaining `init*` calls in main.ts are either callback injection (`initXxxCallbacks`, the constructed subject bundles, `initTimeAdjustmentElements(showFilters)`) or `initSelectionElements()`. *(Risk: medium; eyeball the migrated panel + anything that calls into it.)*
- **D1 — namespace `S.ui`.** ✅ Done. The 29 window/section UI flags (12 `isXxxMinimized` + 16 `isXxxCollapsed` + `isLegendVisible`) are grouped under `S.ui`; all 92 `S.<flag>` references rewritten to `S.ui.<flag>` (scripted, tsc-verified — 0 dangling). The transient interaction guards (`isUpdatingScatterRangeInputs`, `isUpdatingLandScheduleUI`, `isDragging`) were left at the top level — they're not window state. D2–D4 (the rest of `S`) remain opt-in.

### Lower priority / optional
- **D2–D4 — namespace the rest of `S`** (`S.selection`, `S.paint`/`S.layers`, remainder), optionally funneling writes through a `setState()` helper. **Re-evaluate whether it's worth it:** ~499 writes across 22 modules is large churn whose payoff (traceability/undo) is only realized if undo/redo becomes a product goal. Deprioritized unless that's wanted.
- **C1c–C1e — finish selection.ts split** (save/load → `selection-saveload.ts`; tool handlers → `selection-tools.ts`; panel builder → `selection-panel.ts`). Needs a shared `selection-state.ts` (callback seams + mutable state as an object). Medium risk, modest gain — the clean wins are already done.
- **C3b — split comp-finder UI/export** beyond the pure helpers (same state-hoisting friction as C1).
- **E2 — retire callback-injection seams.** 🔄 In progress (safe slice). Strategy: a seam can become a direct `import { fn } from './M'` only when (a) the target lives in a feature module (not `main.ts` — importing from the root is a reverse-dep smell) and (b) it doesn't form an import cycle. **Crucial gotcha:** TypeScript does NOT error on import cycles, so the gate can't catch them — verify the import graph empirically (`grep -rl "from './X'"`), and watch the *bidirectional* trap (converting `A→B` when `B→…→A` already exists closes a loop). Aliased imports (`import { fn as _fn }`) keep call sites untouched. **Done (10 seams):** `statistics` (4) + `scatterplot` (3) — downstream getters into `layers`/`selection`; `selection → windows` (3): `makeDraggable` + `ensureFloatingWindowVisible` as direct imports, and `refreshSelectionControlsDockLayout` became a local `() => window.dispatchEvent(new Event('resize'))` (no dependency at all). Left `registerSelectionControlsDocking` (inline closure mixing main-local `initPinButton` with windows calls — main glue, not a clean import). **Blocked (would cycle):** `modals→layers` (via `layers→filters→modals`); `selection→statistics`/`selection→scatterplot` (those now import selection); `selection→toolbar` (toolbar imports selection); `filters→statistics`/`filters→scatterplot` (statistics/scatterplot import filters). **Next candidates (re-verify the graph empirically first):** `rendering→utils.dom` (`isTextInputElement` — leaf, trivially safe), and the toolbar/windows/comp-finder triangle pending a cycle check. The genuinely-circular remainder (rendering↔layers↔legend) is event-bus territory — deferred; the seams work today.

Bite 1 removed 64 unused-symbol errors; bite 2 fixed the real bugs (TS2552 `ReferenceError`, TS2339 missing props incl. `WRITE` hotkey); bite 3 cleared the remaining 29 (closure narrowing-loss → local-const capture; genuine-null bail guards in `windows.ts`/`time-adjustment.ts`; `props[field ??
